# Open an untitled buffer when a template defines no target

## Context

[#1243](https://github.com/foambubble/foam/issues/1243) reports that `Create
New Note From Template` asks for a title even when the template uses none of
`FOAM_TITLE`, `FOAM_TITLE_SAFE`, `FOAM_SLUG` — the prompt is really the
filename fallback asking for a name. The reporter's underlying request,
which the maintainer endorsed in the issue thread, was different: when the
template doesn't say where the note goes, open the evaluated content in an
unsaved VS Code editor and let them decide on save.

Note creation from a template answers two independent questions, and this
spec keeps them independent. **Whether Foam asks for a title** is decided by
the content: only a template that uses a title variable prompts.
**Whether a file is created** is decided by the target: a template with a
`filepath` (or a flow that supplies one) creates a file; a template without
one opens an unsaved editor. Before this change the second question was
answered by the first — a template without `filepath` was named after the
title, prompting for one if needed — so "a title but no file" was impossible
and "no title" forced a prompt. An interim rule that kept that coupling was
explored on [#1767](https://github.com/foambubble/foam/pull/1767) and
replaced by this one before merge; the prompt-once regression tests already
on `main` (208e4e0, ec8cc58) stay valid.

When a title is known, the unsaved editor is associated with the path the
old flow would have created (`<new-note location>/<title>.md`). In VS Code
1.136.0, saving such an editor writes to that path without a dialog,
creating missing folders, and nothing exists on disk before the save
(verified with a real-VS-Code probe on 2026-11-13). So for the existing
template shape most affected — no `filepath`, uses `FOAM_TITLE` — one save
produces exactly the file the old flow created; the difference is only that
the file appears on save. That is why this ships without a deprecation
period.

The maintainer's constraint: this must not become the out-of-box behavior.
With no `new-note.md` template, the built-in default note text keeps
prompting for a title and creating a file, and the scaffold generated by
`Create New Template` declares a `filepath` so freshly created templates
keep creating files.

## Acceptance criteria

- **AC-1**: Given a markdown template with no `filepath` metadata that uses
  none of `FOAM_TITLE`, `FOAM_TITLE_SAFE`, `FOAM_SLUG`, when a note is
  created from it, then an unsaved markdown editor opens containing the
  resolved template content, no title prompt is shown, and no file is
  written.
  _verify: unit_
- **AC-2**: Given such a template containing VS Code snippet placeholders
  (e.g. `${1:foo}`), when the unsaved editor opens, then the placeholders
  are active for tab-through editing, as they are in file-based creation.
  _verify: unit_
- **AC-3**: Given a template with no `filepath` that uses `FOAM_TITLE`,
  `FOAM_TITLE_SAFE` or `FOAM_SLUG`, when a note is created from it, then
  Foam prompts for the title exactly once, an unsaved editor opens with the
  resolved content, it is associated with `<title>.md` in the location new
  notes go to (as configured by `foam.files.newNotePath`), and no file is
  written until the user saves.
  _verify: unit_
- **AC-4**: Given the associated path of AC-3 already exists, when the note
  is created, then Foam handles it as it handles an existing target today
  (asks for another path by default) before opening the editor, and the
  existing file is left untouched.
  _verify: unit_
- **AC-5**: Given a target path is known — the template declares `filepath`,
  or the flow supplies one (placeholder links, `foam-vscode.create-note`
  with `notePath`) — when the note is created, then a file is created at
  that target and no unsaved editor is involved (unchanged behavior).
  _verify: unit_
- **AC-6**: Given no `new-note.md` template exists, when `Create New Note`
  runs, then the built-in default note text prompts for a title and creates
  a file (unchanged behavior).
  _verify: unit_
- **AC-7**: Given a daily-note template with no `filepath`, when a daily
  note is created, then the file is created at the configured daily-note
  location, never an unsaved editor.
  _verify: unit_
- **AC-8**: Given `Create New Template` generates its scaffold, then the
  scaffold declares a `filepath` in its template metadata that names the
  note from the title prompt (the path uses a title variable), so creating
  a note from the unmodified scaffold prompts for a title and creates a
  file, and a second note from the same scaffold does not collide with the
  first.
  _verify: unit_
- **AC-9**: Given a template that uses `FOAM_SELECTED_TEXT` and text is
  selected in the active editor, when a note is created into an unsaved
  editor, then the selected text is included in the buffer content and the
  original selection is left as it was — it is not replaced with a
  wikilink, since the note does not exist yet and may never be saved.
  _verify: unit_
- **AC-10**: Given the templates documentation, then it states that the
  title prompt appears only for the title variables, and that a template
  without `filepath` opens an unsaved editor, named after the title when
  the template uses one.
  _verify: human_

## Out of scope

- Non-editor clients (CLI, MCP): they cannot open buffers and keep their
  current file-creating behavior and naming.
- Any setting, command, or template metadata to opt in or out of the buffer
  behavior. The trigger is the template's own shape.
- A deprecation period for templates without `filepath` that use a title
  variable: their saved result is unchanged (see Context).
- Other Save-As-centric ideas from the #1243 thread (Explorer context menu,
  intercepting the New File button).
- Linking or graph participation for unsaved notes: a note enters the
  workspace model once saved, as today.

## Open questions

- `foam-vscode.create-note` called with `text` but no `notePath` (e.g. from
  a keybinding) follows the same rule as a template without `filepath`, so
  it now opens unsaved. Assumed acceptable: `notePath` is that command's
  target, and callers who want a file pass one.
